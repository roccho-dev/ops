# contract-diff

Pure finite comparison for [ops#493](https://github.com/roccho-dev/ops/issues/493),
[envs#47](https://github.com/roccho-dev/envs/issues/47) and the reviewed
[ADRS #541 design](https://github.com/roccho-dev/adrs/pull/541).

## Boundary

The core accepts normalized rows and an **independently admitted** scope, universe,
input inventory and evidence digest set. It does not acquire or authenticate those
inputs, discover ADRS obligations, choose the scope, select latest evidence, call a
provider, or grant organizational admission. Supplying two matching JSON files is
not proof that their producer is trusted. Production acquisition and Phase 2
policy/admission remain with their existing owners.

Missing admission/acquisition is UNKNOWN, not an empty successful scope. Empty
evidence is normal only when the accepted profile requires none; explicitly
conflicting references are invalid even then. Structural, contract and evidence
findings are distinct. Every normal result binds its admitted input manifest and
exact source identities; volatile execution metadata does not enter this result.

## Use

```text
contract-diff --input input.json --admission admitted.json
contract-diff --selftest
```

Exit codes: CLOSED=0, OPEN=2, INVALID=3, UNKNOWN=4. All results have
`authority:false`. Scope grade `fixture` or `source` describes the input boundary,
not a claim of successful provider use. The `real` value in an evidence profile
means real evidence is **required**, not that such evidence exists.

Inputs have four source-bound collections: required, provided, observations and
receipts. `core.py` owns their closed structural schema. A source identifies the
repository, exact commit, path and content digest. The separately admitted
inventory supplies each source, canonical row digest and row count. The universe
supplies stable obligation IDs, accepted meaning digests and required evidence
profiles. The core never invents those identities.

## Generate the voice-ui requirement from its actual owner

```text
voice-ui-target-runtime --requirements selected.json
```

The request contains `target` (the existing Workers target shape) and `obligation`
with `id`, `obligation_digest`, and `binding`. Obtain these from the approved scope;
do not mint a production ID in this consumer. The installed runtime supplies its
own source revision and derives R from the same values its handoff validator and
artifact admission enforce. It does not read an envs checkout, request a secret,
validate a real receipt, deploy, or run application acceptance. Output is generated
on stdout; there is no second handwritten requirement file.

This projection covers the declared capability, stage, target, slot, binding and
required effect/readback profile. It does not replace the existing full handoff,
artifact, workflow-provenance or deployment validators.

## Checks and fixture provenance

```text
nix build .#checks.x86_64-linux.contract-diff
nix build .#checks.x86_64-linux.contract-diff-source-integration
```

The first tests the installed core/CLI without an ambient interpreter launcher.
The second uses the real runtime requirement generator and receipt validator,
then invokes the installed comparator from fresh processes.

`tests/fixtures/envs-pages-provision.json` was generated by envs PR48 at
`1f4eeb74724c68eaf98ab96784c3408409e9a7fc`, using the exact public binding and
consumer files. The generator blob is `612212f7989d960f5574b541dfccd527c345b79d`;
the input blobs are `43bda8f8205436cea429a58331193b2861cd56d2` and
`b8b384ab994c875692223dfd904abcb67857cc92`. Its selector is the clearly marked
fixture obligation in `source-integration.mjs`. It is frozen regression data,
not a current live readback, an authenticated receipt or an accepted ADRS scope.
The source integration must report both target drift and missing required evidence.
Changing Pages to Workers in test data alone must not produce CLOSED.

V24-V28 production-governance integration and V30 real application/provider gates
are not proven by these finite tests. Detector success does not imply Workers
remediation, independent R approval, deployment, or #443 completion.
