# Role boundaries — 別契約の開発用suite

期待：目標宣言と観測の意味を、引用・チェックリスト・HTMLコメント・受入例・見出し・検査対象内の指示から区別できること。旧8件や旧結果を変更しない。

`TRIAL_SUITE=role-boundaries` を指定し、同じ `run.mjs evaluate/score` を使う。候補は共有 `candidates/`、問題・Gold・契約だけがこのsuiteに属する。入力/参照ラベル/採点の契約は候補間で変えない。応答モデル版が異なれば停止する。

8件×最大2候補、16 calls。基準が8/8なら変更0。未達なら失敗を読んで1候補だけ改善し、同条件で比較する。再実行・停滞・契約不一致・予算不明は停止。実行予約は同じ出力先の重複を拒否するが、別CI run間の永続予約・自動再開はP4の別契約であり実装済みとしない。

同じ作成者の合成開発例。独立GoldでもHoldoutでもなく、基本完成P3の品質証拠にはしない。基準候補の性能、実行状況、反復の結果はIssue/PRコメントと実CI結果に記録する。
