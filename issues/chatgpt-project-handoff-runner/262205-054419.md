# ChatGPT Project handoff runner

## 課題

- Project Source upload、thread create/send、5分以上 readback、artifact 受領までを一貫実行する入口が弱い。
- 既存 CDP / ops-cdp-core route はあるが、handoff task が毎回どの wrapper を使うべきか迷いやすい。
- runner がないと、Project Source-only rule や threadFunction binding の遵守が手作業になる。

## 影響

- thread attachment fallback や inline 長文 fallback が混ざる。
- ChatGPT thread が bootstrap artifact を読めたことを確認しないまま作業が進む。
- artifact 受領、hash、readback、claim 化が抜ける。

## close 条件

- `chatgpt-project-handoff-runner` が Project Source-only rule を守って handoff を実行する。
- runner は `project-source-put`、thread create/send/readback、artifact fetch/import を wrapper-first で使う。
- 5分未満 readback を semantic judgment にしない。
- output は claim / evidence として取り込める JSON を返す。
