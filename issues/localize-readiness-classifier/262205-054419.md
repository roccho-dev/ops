# localize readiness classifier

## 課題

- localizer 向け資料、Project handoff 済み資料、merge-review-pass 受領済み資料を機械的に区別する入口がない。
- 状態名だけでは、どの review route を通ったか、どの artifact が evidence かを判定しづらい。
- actor が `ready-for-localizer` を広く使うと、未review の資料が localize 対象に見える。

## 影響

- canonical merge 前の判断が弱くなる。
- Project handoff が未実施なのに、localize-ready と誤認する。
- merge-review-pass 受領済みかどうかの確認が手作業になる。

## close 条件

- evidence bundle / LOCALIZE_READY / claim / readback を読み、`local-handoff-ready`、`project-handoff-sent`、`project-review-ready`、`merge-review-pass-received` を分類する。
- 分類不能な場合は不足 field と requiredOwner を返す。
- 分類結果は JSON evidence として localizer が読める。
